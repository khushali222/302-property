RMOB-101
total_amount sent as (amount − surcharge) — backend rejects with 400
Critical Admin Staff make_payment edit_payment
✅ Fixed ● High
▶
Root Cause
Admin and Staff storePayment() / storePaymentAch() calculated total_amount = amount − surcharge. But amount is already the base rent (e.g. 1.00), not a value that includes surcharge. Subtracting gives 0.92. The backend (PaymentService.js addPayment) validates sum(entries) === total_amount. Entries sum = 1.00 ≠ 0.92 → HTTP 400 rejected.
Backend Ref
PaymentService.js → addPayment(): integrity check if (entrySum !== totalAmount) throw 400
Files Fixed
lib/repository/payment/payment_service.dart
lib/StaffModule/repository/payment/payment_service.dart
lib/repository/payment/Edit_payment.dart
lib/StaffModule/repository/payment/Edit_payment.dart
// BEFORE (broken) — Admin & Staff storePayment / storePaymentAch / Edit - 'total_amount': (double.parse(totalAmount) - double.parse(surcharge)), // AFTER (fixed) + 'total_amount': double.parse(totalAmount), // send base rent as-is
✅ Why this is correct Backend backend auto-adds a surcharge line-entry and increments its own stored total. Mobile must send the base rent unchanged. The surcharge is sent separately in its own field so the backend can validate it.

RMOB-102
Scheduled payments saved as "SUCCESS" instead of "PENDING"
Critical Admin Staff scheduled_payment
✅ Fixed ● High
▶
Root Cause
storePaymentfornormal() in Admin and Staff had 'response': "SUCCESS" hardcoded. For scheduled/future payments the backend sets status = PENDING (date > today) and the NMI charge has NOT run yet. Saving "SUCCESS" causes the record to appear paid when it isn't.
Backend Ref
NMIService.js processAchSale: if payment date > today → store as PENDING task. Status must match actual NMI response text.

RMOB-103
[Admin/Staff] tenant_id (snake_case) missing from NMI Card & ACH payloads — permission gate bypassed
Critical Admin Staff NMI card ach
✅ Fixed ● High
▶
Root Cause
Admin and Staff makePaymentforcard() and makePaymentforach() sent tenantId (camelCase) but the backend NMI routes check paymentDetails?.tenant_id (snake_case only). Without the snake_case key the allow_card / allow_ach permission gate is silently bypassed — the tenant's payment method restrictions are never enforced.
Backend Ref
NMI-response.js /sale: reads paymentDetails?.tenant_id to look up tenant and check allow_card
NMI-response.js /ACH_sale: same check for allow_ach
Files Fixed
lib/repository/payment/payment_service.dart
lib/StaffModule/repository/payment/payment_service.dart
// BEFORE — only camelCase sent - 'tenantId': tenantId, // AFTER — both forms sent so NMI-response.js can read snake_case + 'tenantId': tenantId, // kept for any other usage + 'tenant_id': tenantId, // required by NMI-response.js allow_card / allow_ach check
