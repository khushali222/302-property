## CRITICAL

### C1. App points to STAGING server
- `lib/constant/constant.dart:14, 22, 26` — All 3 base URLs (API, image fetch, image upload) are hardcoded to `https://staging.cloudrentalmanager.com`; production URLs are commented out.
- Related: `lib/services/app_headers.dart:70` maps any `staging.` URL to the `testflight` channel → build is exempt from force-update enforcement.

### C2. Vendor dashboard always crashes / blank
- `lib/VendorModule/screen/dashboard.dart:105,110` — reads `prefs.getString("tenant_id")` (never set for vendors; login stores `vendor_id`) then force-unwraps `${id!}` → guaranteed null crash.
- Same in `fetchDatafinancial()` at `:147,153` — also calls the wrong (tenant) endpoint.
- `:122-126,166` — `countList` is an empty list assigned by index (`countList[2] = ...`) → `RangeError` every call, swallowed by catch at `:177` → dashboard tiles permanently blank.
- 8 more copy-pasted `getString("tenant_id")` in VendorModule: `repository/tenant_financial.dart:14`, `repository/tenant_repository.dart:13`, `repository/workorder.dart:150`, `screen/work_order/add_workorder.dart:267,313,1137`, `screen/change_password.dart:1403` — null id in URL and auth header → 401/500.

### C3. Payment: retry can double-charge (idempotency broken in Edit_payment)
- `lib/repository/payment/Edit_payment.dart:479` (also 223, 368, 584, 639) — `"X-Idempotency-Key": Uuid().v4()` regenerated on EVERY attempt; no idempotencyKey param exists. Retry of `ACH_sale` = new key = charged again.
- `payment_service.dart:111` has same weakness when callers omit the optional arg.
- `CustomAddSubscriptionService.dart` (Preminum Plans) sends NO idempotency key at all, and treats HTTP-200 declined subscription as success (`response_code` never checked; `jsonResponse['transactionid']` cast crashes on null) — lines 26-35.

### C4. Payment: ledger write not awaited after successful charge
- `Edit_payment.dart:489` — `storePaymentAch(...)` fired without `await` right before `return "Payment Success"`. Card charged, ledger PUT may silently fail, UI reports success. (Sibling call sites at 150, 302, 516 all await.)

### C5. Payment: no HTTP timeouts anywhere
- `lib/services/api_helpers.dart:79,92,110,128,146` — no `.timeout()` on any call; zero timeouts in all of `lib/repository`. Stalled `/api/nmipayment/sale` = spinner forever → user force-quits and pays again.

### C6. Login crashes on force-unwraps
- `lib/screens/Login/login_screen.dart:6304` — `prefs.setString('adminId', adminId!)` on nullable field from login response → crash mid-login.
- `:6345` — `userId!` force-unwrap; single-company/single-role logins where roles never populated crash AFTER token persisted → half-authenticated app.
- `:6338` — `json.decode(response.body)` with no statusCode check / try-catch; HTML 502 page → FormatException, `loading` never reset, login button dead.

### C7. Tenant drawer crashes (permissions null)
- `lib/TenantsModule/widgets/custom_drawer.dart:106,119,132,151` — `permissions!.propertyView` force-unwrap; `_loadPermissions()` is commented out (line 28), null guards commented out (49-56). Opening drawer from dashboard/profile/change-password throws.
- Root cause amplifier: `lib/TenantsModule/model/permission.dart:32-42` — all 10 bools assigned raw `json[...]` with no `?? false`; any missing key throws in fromJson, swallowed in `permission_provider.dart:17`, leaving permissions null. Same in `VendorModule/model/vendor_permission_model.dart:19-21`.
